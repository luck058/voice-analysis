# Task: vibrato

## Goal

Implement vibrato detection from a pitch track, returning the rate in Hz and extent in cents for sustained oscillations between 3-9 Hz with sufficient amplitude, or null when no vibrato is detected.

## Requirements

1. detectVibrato must accept a track of PitchPoint objects in time order and return a Vibrato object with rateHz and extentCents properties, or null
2. The function must handle irregularly spaced points by splitting tracks at gaps > 0.1 seconds and using the longest contiguous run
3. A valid vibrato run must span at least 1.0 seconds and contain at least 20 points, otherwise return null
4. Remove linear trend from the pitch points before analysis to isolate oscillation from pitch drift
5. Calculate rateHz as the dominant periodicity of the detrended run (e.g., via zero crossings or autocorrelation peak after resampling to 100 points per second)
6. Calculate extentCents as half the mean peak-to-trough excursion of the detrended run
7. Return null when rateHz is outside [minRateHz, maxRateHz] or extentCents < minExtentCents (defaults: minRateHz=3, maxRateHz=9, minExtentCents=10)
8. The implementation must pass tests including: 5.5Hz/50cents sine wave, same with linear drift, flat track, too slow (1Hz), too small (5cents), too short (0.8s), and track with gap

## Files in scope

- `src/analysis/vibrato.ts`

## Context

This is a new feature with no dependencies. Follow TypeScript conventions: named exports only, explicit types, Float32Array for audio data. Invalid input throws RangeError; 'no answer' returns null. The PitchPoint interface has timeSec and cents properties. The Vibrato interface has rateHz and extentCents properties. Tests will be written separately by a test-writer agent.

## How to run the tests

Run the tests before finishing. The harness independently re-runs them and
rejects the task if its trajectory shows no real test run.

The test tooling is installed for you before this session starts, by
`.openhands/setup.sh`. Normally you only need the run command below.
Do not reinstall the project's dependencies yourself (`npm ci`, `npm install`,
`pip install -r ...`): the test tooling is not in the project's manifest, so
a reinstall removes it.

### Commands

Run the tests:

    npx --no -- jest --ci

If that reports the test runner is missing, the pre-install failed.
Re-run it yourself, passing the terminal tool's `timeout` parameter as at
least 900 seconds (otherwise the command is
paused after 30 seconds with no new output and reports exit code -1 while
it is still running):

    if [ -f package.json ]; then ( npm ci --no-audit --no-fund || npm install --no-audit --no-fund ) || exit 1; fi; npm install --no-audit --no-fund --no-save jest@29 ts-jest@29 typescript @types/jest jest-junit || exit 1; printf "%s\n" "module.exports = { testEnvironment: \"node\", transform: { \"^.+[.]tsx?$\": [\"ts-jest\", { diagnostics: false }] }, testMatch: [\"**/*.test.ts\", \"**/*.test.tsx\", \"**/*.spec.ts\", \"**/*.spec.tsx\"], moduleNameMapper: { \"^([.]{1,2}/.*)[.]js\$\": \"\$1\" } };" > jest.config.js

and then run the tests again.
