# Task: signal_basics

## Goal

Implement deterministic signal generators for testing, FFT operations for spectral analysis, and level measurement functions. These are foundational DSP modules that will be used by all subsequent audio analysis components.

## Requirements

1. sine() must generate a pure sine wave at the specified frequency, amplitude, and phase
2. harmonicTone() must generate a band-limited sawtooth wave with harmonics up to the specified count, scaled to the given amplitude
3. vibratoTone() must generate a sine wave with frequency modulation following the specified vibrato rate and extent, using phase accumulation for smooth transitions
4. whiteNoise() must generate deterministic pseudo-random noise using the mulberry32 PRNG, with the same seed always producing the same samples
5. pulseTrain() must generate a series of raised-cosine pulses at the specified time intervals
6. resonate() must apply a cascade of Klatt two-pole resonators to filter a signal according to the given formant frequencies and bandwidths
7. mix() must perform sample-wise addition of two signals, handling different lengths by using the longer signal's length
8. scaleToRms() must scale a signal to achieve the specified RMS level in dBFS
9. hannWindow() must generate a symmetric Hann window with the correct values at all points
10. fft() must perform an in-place radix-2 FFT on complex arrays, throwing RangeError for invalid inputs
11. magnitudeSpectrumDb() must compute the dB magnitude spectrum of a frame with Hann windowing and proper normalization
12. binFrequency() must compute the frequency of an FFT bin given sample rate and frame size
13. rmsDbfs() must compute the RMS level in dBFS, returning -120 for silence
14. peakDbfs() must compute the peak level in dBFS, returning -120 for silence

## Files in scope

- `src/testing/synth.ts`
- `src/dsp/fft.ts`
- `src/dsp/level.ts`

## Context

All modules must be pure TypeScript with no DOM or browser APIs. Use Float32Array for audio signals. Invalid inputs should throw RangeError with descriptive messages. 'No answer' cases (like silence) should return null or a sentinel value, not throw. All exported functions must have explicit type annotations. Use ES module syntax (import/export). The config.ts module with constants like DEFAULT_SAMPLE_RATE exists but is not required for these implementations.

## How to run the tests

Run the tests before finishing. The harness independently re-runs them and
rejects the task if its trajectory shows no real test run.

The test tooling is installed for you before this session starts, by
`.openhands/setup.sh`. Normally you only need the run command below.
Do not reinstall the project's dependencies yourself (`npm ci`, `npm install`,
`pip install -r ...`): the test tooling is not in the project's manifest, so
a reinstall removes it.

### Commands

Run the tests:

    npx --no -- jest --ci

If that reports the test runner is missing, the pre-install failed.
Re-run it yourself, passing the terminal tool's `timeout` parameter as at
least 900 seconds (otherwise the command is
paused after 30 seconds with no new output and reports exit code -1 while
it is still running):

    if [ -f package.json ]; then ( npm ci --no-audit --no-fund || npm install --no-audit --no-fund ) || exit 1; fi; npm install --no-audit --no-fund --no-save jest@29 ts-jest@29 typescript @types/jest jest-junit || exit 1; printf "%s\n" "module.exports = { testEnvironment: \"node\", transform: { \"^.+[.]tsx?$\": [\"ts-jest\", { diagnostics: false }] }, testMatch: [\"**/*.test.ts\", \"**/*.test.tsx\", \"**/*.spec.ts\", \"**/*.spec.tsx\"], moduleNameMapper: { \"^([.]{1,2}/.*)[.]js\$\": \"\$1\" } };" > jest.config.js

and then run the tests again.
