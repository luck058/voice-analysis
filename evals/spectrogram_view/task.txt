# Task: spectrogram_view

## Goal

Implement the SpectrogramModel class that creates and updates a scrolling spectrogram visualization. The model converts frequency-domain data (dB spectrum) into a coloured image with time on the horizontal axis and log-spaced frequency on the vertical axis, suitable for real-time display.

## Requirements

1. The constructor must accept width, height, sampleRate, and frameSize as required parameters, with optional minHz, maxHz, minDb, maxDb defaults as specified.
2. The image property must be a Uint8ClampedArray of width*height*4 RGBA bytes, initialized to opaque black (0, 0, 0, 255).
3. hzForRow(row) must return the frequency in Hz for a given row, with row 0 corresponding to maxHz and row height-1 to minHz, using logarithmic spacing.
4. rowForHz(hz) must return the nearest row index for a given frequency, clamped to valid row range, and be the inverse of hzForRow.
5. colourFor(db) must map a dB value to RGB colour using the five specified colour stops with linear interpolation, clamping db to [minDb, maxDb].
6. push(spectrumDb) must shift the entire image left by one pixel and draw a new column at the rightmost position, with each row coloured according to the spectrum value at that row's frequency, interpolated between nearest bins.

## Files in scope

- `src/views/spectrogram.ts`

## Context

Follow TypeScript conventions: named exports only, explicit types on all exports. The src/views modules are pure (no DOM, no timers, no random). Invalid parameters (e.g., negative width) should throw RangeError with a descriptive message. The signal_basics dependency (fft.ts, level.ts, synth.ts) is already implemented and verified - you can import from them if needed, but this spectrogram model only needs the spectrumDb input, not the raw audio.

rejects the task if its trajectory shows no real test run.

`.openhands/setup.sh`. Normally you only need the run command below.
