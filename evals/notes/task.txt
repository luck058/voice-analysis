# Task: notes

## Goal

Implement the music note conversion functions that convert between frequency, MIDI note numbers, note names, and cents. These functions will be used by the pitch detector to display the musical note information for detected pitches.

## Requirements

1. hzToMidi(hz, a4 = A4_HZ) must return fractional MIDI number using formula 69 + 12*log2(hz/a4)
2. midiToHz(midi, a4 = A4_HZ) must return frequency using the inverse formula a4 * 2^((midi - 69)/12)
3. noteName(midi: number) must return string in scientific pitch notation with sharps only (e.g., 60 -> 'C4', 61 -> 'C#4', 69 -> 'A4', 21 -> 'A0')
4. hzToNote(hz, a4 = A4_HZ) must return NoteInfo with nearest integer MIDI, note name without octave, octave number, and cents in range [-50, 50)
5. hzToMidi and hzToNote must throw RangeError when hz is not a finite number above 0
6. All functions must handle the 50-cent boundary correctly: a pitch exactly 50 cents above a note belongs to the next note at -50 cents

## Files in scope

- `src/music/notes.ts`

## Context

This is a new feature with no dependencies. Follow TypeScript conventions: named exports only, explicit types, ES module syntax. Use A4_HZ from src/config.ts. The NoteInfo interface is defined in architecture.md: { midi: number; name: string; octave: number; cents: number }. Note names use sharps only, not flats. Cents must be in range [-50, 50).

## How to run the tests

Run the tests before finishing. The harness independently re-runs them and
rejects the task if its trajectory shows no real test run.

The test tooling is installed for you before this session starts, by
`.openhands/setup.sh`. Normally you only need the run command below.
Do not reinstall the project's dependencies yourself (`npm ci`, `npm install`,
`pip install -r ...`): the test tooling is not in the project's manifest, so
a reinstall removes it.

### Commands

Run the tests:

    npx --no -- jest --ci

If that reports the test runner is missing, the pre-install failed.
Re-run it yourself, passing the terminal tool's `timeout` parameter as at
least 900 seconds (otherwise the command is
paused after 30 seconds with no new output and reports exit code -1 while
it is still running):

    if [ -f package.json ]; then ( npm ci --no-audit --no-fund || npm install --no-audit --no-fund ) || exit 1; fi; npm install --no-audit --no-fund --no-save jest@29 ts-jest@29 typescript @types/jest jest-junit || exit 1; printf "%s\n" "module.exports = { testEnvironment: \"node\", transform: { \"^.+[.]tsx?$\": [\"ts-jest\", { diagnostics: false }] }, testMatch: [\"**/*.test.ts\", \"**/*.test.tsx\", \"**/*.spec.ts\", \"**/*.spec.tsx\"], moduleNameMapper: { \"^([.]{1,2}/.*)[.]js\$\": \"\$1\" } };" > jest.config.js

and then run the tests again.
