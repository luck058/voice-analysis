# Task: pitch

## Goal

Implement the YIN pitch detection algorithm to find the fundamental frequency of an audio frame. This will enable the voice coach to show the user's pitch in Hz, the nearest musical note, and how many cents sharp or flat they are relative to that note when they make a voiced sound, and show 'no pitch detected' when the input is silent or unvoiced.

## Requirements

1. The detectPitch function must implement the YIN algorithm: compute the difference function d(tau) for tau up to sampleRate/minHz, compute the cumulative mean normalized difference d'(tau), find the first tau in [sampleRate/maxHz, sampleRate/minHz] where d' drops below threshold, walk to the bottom of that dip, use parabolic interpolation for fractional lag, and compute hz = sampleRate / lag.
2. clarity = 1 - d'(lag), clamped to [0, 1].
3. Return null when rmsDbfs(frame) < SILENCE_DBFS, when no lag in range goes below threshold, or when the result would fall outside [minHz, maxHz].
4. Throw RangeError when the frame is shorter than 2 * sampleRate / minHz samples.
5. Use default parameters: minHz = PITCH_MIN_HZ from config.ts, maxHz = PITCH_MAX_HZ from config.ts, threshold = 0.15.
6. Performance: 50 calls on 2048-sample frames at 48 kHz must take under 2 seconds total in the test environment.

## Files in scope

- `src/dsp/pitch.ts`

## Context

Use ES module syntax (import/export). Type every parameter and return value explicitly. The signal_basics dependency is already implemented: you can import and use rmsDbfs from src/dsp/level.ts, and PITCH_MIN_HZ, PITCH_MAX_HZ, SILENCE_DBFS from src/config.ts. Tests will be written separately; your implementation must pass them. Invalid input throws RangeError with a message naming the parameter. 'No answer' (silence, unvoiced audio) returns null, never an exception or NaN.

## How to run the tests

Run the tests before finishing. The harness independently re-runs them and
rejects the task if its trajectory shows no real test run.

The test tooling is installed for you before this session starts, by
`.openhands/setup.sh`. Normally you only need the run command below.
Do not reinstall the project's dependencies yourself (`npm ci`, `npm install`,
`pip install -r ...`): the test tooling is not in the project's manifest, so
a reinstall removes it.

### Commands

Run the tests:

    npx --no -- jest --ci

If that reports the test runner is missing, the pre-install failed.
Re-run it yourself, passing the terminal tool's `timeout` parameter as at
least 900 seconds (otherwise the command is
paused after 30 seconds with no new output and reports exit code -1 while
it is still running):

    if [ -f package.json ]; then ( npm ci --no-audit --no-fund || npm install --no-audit --no-fund ) || exit 1; fi; npm install --no-audit --no-fund --no-save jest@29 ts-jest@29 typescript @types/jest jest-junit || exit 1; printf "%s\n" "module.exports = { testEnvironment: \"node\", transform: { \"^.+[.]tsx?$\": [\"ts-jest\", { diagnostics: false }] }, testMatch: [\"**/*.test.ts\", \"**/*.test.tsx\", \"**/*.spec.ts\", \"**/*.spec.tsx\"], moduleNameMapper: { \"^([.]{1,2}/.*)[.]js\$\": \"\$1\" } };" > jest.config.js

and then run the tests again.
